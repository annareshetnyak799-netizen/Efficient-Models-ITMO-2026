# ДЗ 1. Аналитическая модель стоимости CNN

Выведены и проверены функции FLOPs, памяти, времени и энергии одного forward
для батча из B изображений S × S. Все 132 конфигурации выполнены успешно,
энергия измерена для каждой, OOM не наблюдался.

## Окружение

Google Colab, одна Tesla T4, 15 637 086 208 байт видеопамяти.
Python 3.13.15, PyTorch 2.11.0+cu128, CUDA 12.8, драйвер 580.82.07,
cuDNN 91900 (значение API), NumPy 2.1.3, SciPy 1.16.3, pandas 2.2.3.

## Воспроизведение

1. Откройте [measure.ipynb](measure.ipynb) в Colab с T4 GPU.
2. Загрузите `models.py`, `equations.py`, `calibrate.py` в `/content`.
3. Выполните ячейки сверху вниз. Первая устанавливает дополнительные
   библиотеки, PyTorch с CUDA предоставляется средой Colab.
4. Скачайте созданную папку `results/` и сохраните выполненный ноутбук

Для локального запуска используйте NVIDIA GPU до 16 ГБ и откройте ноутбук
из папки `hw1/`. При повторном эксперименте задайте новую папку `RESULTS`
в ячейке настроек: существующие измерения защищены от перезаписи при запуске
проверки окружения. Для энергии необходим доступ к NVML.

## Протокол и допущения

- Случайные входы, seed 42; FP32, `eval()`, `inference_mode()`.
  `cudnn.benchmark` и оба флага `allow_tf32` выключены.
- 10 прогревочных проходов, latency — медиана 30 отдельных wall-clock
  измерений с CUDA-синхронизацией. Генерация входа исключена.
- Memory — `max_memory_allocated()` за отдельный forward после сброса пика,
  параметры и вход включены.
- Energy — разность счётчика NVML за серию не менее 3 секунд, деленная
  на число проходов. Учитывается вся GPU, мощность простоя не вычитается.
- 63 пары базовой сетки — калибровка, 69 пар с дополнительным S или B —
  независимая проверка.
- В сети шесть сверток с ReLU, BatchNorm нет, у Linear принят bias.
  1 MAC = 2 FLOPs, сравнения исключены из арифметического счета.
- Память моделируется суммой параметров входа
  и активаций без повторного счета inplace-хранилищ и без рабочих буферов.
  Трафик предполагает одно чтение входа и параметров и одну запись выхода.
- Latency — постоянные расходы плюс сумма послойных максимумов времени
  арифметики и передачи данных. Energy = latency × средняя мощность.
  Калибровка минимизирует квадраты логарифмических ошибок только на
  калибровочной части сетки.

## Результаты

Ошибки на 69 проверочных точках. MAPE — среднее значение
`100 × |прогноз − измерение| / измерение`.

| Величина | MAPE | Максимальная ошибка |
|---|---:|---:|
| Память | 16,81% | 79,92% |
| Время | 20,66% | 62,53% |
| Энергия | 17,04% | 53,71% |

FLOPs совпали с подсчётом по исполненным слоям во всех 132 случаях.
Это проверка архитектуры и формул, а не измерение аппаратных инструкций.

Коэффициенты: t₀ = 0,359 мс, P_eff = 5,735 × 10¹² FLOP/с,
BW_eff = 78,408 × 10⁹ байт/с, средняя мощность = 66,448 Вт.
Это параметры приближённой модели, а не паспортные характеристики GPU.

## Обсуждение

**Память.** На малых входах ручная формула недооценивает пик: при S=80, B=1
прогноз составляет 4,83 МБ, измерение — 24,05 МБ. Возможная причина —
неучтенные рабочие буферы, существенные относительно малых активаций.
На больших входах сумма активаций может завышать пик из-за освобождения
промежуточных тензоров. Точный вклад буферов этим экспериментом не установлен.

**Время и режимы.** При B=1 время для S=32, 64 и 224 близко:
0,503, 0,519 и 0,515 мс. Это согласуется с существенными накладными расходами
на малых нагрузках (launch-bound). При S=400, B=1 модель завышает время
с 0,831 до 1,351 мс, при S=512, B=256 занижает с 564,4 до 411,2 мс.
Постоянные эффективные скорости не описывают все размеры одинаково хорошо.
Влияние выбранных алгоритмов и загрузки GPU — возможное объяснение.
На больших конфигурациях модель учитывает и memory-bound, и compute-bound
операции. Четкая последовательность 3х режимов для сети экспериментально
не доказана. Одного увеличения FLOPs недостаточно для определения режима.

**Энергия.** Коэффициент 66,448 Вт близок к средней мощности энергетических
серий, около 65,76 Вт. Однако модель наследует ошибки latency и не учитывает
изменения мощности. Наибольшая проверочная ошибка — недооценка на 53,71%
при S=32, B=179. Энергия усредняется по серии, а latency — медиана отдельных
проходов, различие протоколов и разрешение телеметрии ограничивают точность.

**OOM.** Ни измерения, ни модель не показали OOM. Максимальный пик — 5,75 GiB,
максимальный прогноз — 6,50 GiB, оба относятся к S=512, B=256 и меньше
памяти T4. Поэтому точность предсказания самой границы OOM проверить
не удалось.
